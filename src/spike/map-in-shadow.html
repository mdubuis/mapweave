Phase 1 spike — legacy map engine inside a Shadow DOM

Dev-only harness for the Phase 6 single-DOM-merge plan (see MAPWEAVE.md). Boots the real map engine — the actual map.html body, the actual classic scripts, the actual boot() — inside a shadow root, using src/services/shadow-dom-bridge.ts's light-DOM-first fallback patch. Not wired into the production app; not part of the build (excluded from vite.config.ts's rollupOptions.input) — only reachable via npm run dev.

Manual verification checklist (see console for progress/errors):

  1. No console errors during boot.
  2. The map actually draws inside the boxed area below (not blank, not drawn outside the box).
  3. Open a dialog that uses jQuery UI (e.g. click a burg to open the burg editor, or use a menu that opens an options dialog) — it should render inside the boxed area, correctly styled, not floating unstyled at the bottom of this page.
  4. Pan/zoom the map — no visible double-transform/offset glitch.
  5. In devtools, inspect #spike-host → open its shadow root → confirm the map SVG, Leaflet container, and any open dialog all live inside it, not as light-DOM children of <body>.
